1. 고정된 연구 목표

FULL anchor → 1초 DELTA → DELTA → … → learned COMMIT → CAPTION → FULL refresh → … → FINAL ANSWER

  • Video와 audio는 pinned Qwen2.5-Omni native encoder를 사용한다.
  • DeltaTok은 modality별 독립 encoder/decoder이며 한 블록당 정확히 delta token 하나를 만든다.
  • LLM 학습은 항상 Qwen Thinker LoRA다. Full fine-tuning은 하지 않는다.
  • 한 sequence에서 commit/caption/full refresh가 여러 번 발생해야 한다.
  • 최종 QA는 이전 committed caption memory와 현재 synchronized A/V state를 함께 사용해야 한다.

Model: Qwen/Qwen2.5-Omni-7B, revision ae9e1690543ffd5c0221dc27f79834d0294cba00. 직접 측정된 1초 블록은 video 64×3584, audio 25×3584이고 delta는 modality별 1×768이다.

3. 최신 vanilla Qwen2.5-Omni baseline

Baseline code revision은 933b0f92b3a0a844daa54e768585b724a40b4c27이다. 기존 Stage 3와 동일한 16개 source-disjoint short NExT-QA test video의 132문항을 사용했고, 별도로 16개 short MSR-VTT test video를 요약했다. Native raw audio/video를 2 fps, 224×224로 입력하고 greedy text generation을 사용했다.

4. Caption CE/LoRA 상태

  • CE/NLL은 실제 Qwen Thinker causal LM token loss에 적용된다. Trainable parameter는 PEFT LoRA와 delta interface뿐이고 audio/vision tower는 frozen이다.
  • 2초 AudioCaps 8K run은 validation으로 200-step checkpoint를 선택했고 untouched test에서 normal이 zero/shuffle을 NLL과 실제 generated caption metric 모두 이겼다. 이것이 현재 가장 강한 S2 증거다.
  • 1초 AudioCaps 1K run은 delta control gap은 있지만 held-out 개선에 실패했다. 이를 caption 학습 성공으로 표기하면 안 된다. 최소 8K–10K caption으로 1초/9-delta 조건을 다시 학습해야 한다.
  • Multi-commit caption aggregate는 위 1K checkpoint를 반복 호출한 historical mechanics PoC다. tracked producer가 없고 cross-sequence shuffled timing F1도 1.0이므로 research evidence가 아니다.

6. 아직 해결되지 않은 핵심 문제

  1. 실제 Qwen Stage 3 부재: typed video/audio delta와 caption memory를 Qwen Thinker LoRA가 소비하는 QA 학습 코드가 아직 없다.
  2. Video rollout drift: 9초에서 teacher-forcing 대비 약 54.8% drift. 우선 4–5초 FULL refresh 또는 reconstructed-previous/scheduled rollout 학습이 필요하다.
  3. Natural commit: 고정 9초 label F1 100%는 의미 없다. 가변 event boundary와 no-event negative가 필요하다.
  4. 1초 caption scale: 1K는 overfit. 최소 8K–10K caption으로 동일 granularity에서 다시 확인해야 한다.
  5. Baseline controls 완료: multimodal/text-only/video-only/audio-only가 77.27/48.48/81.06/55.30%였다. 실제 Stage 3는 video anchor+delta LoRA부터 시작한다.
  6. Media policy: internal non-commercial research만 허용하며 raw media/recoverable embedding 공개는 금지한다. 외부 release 전 per-item YFCC100M license metadata audit가 필요하다.
  7. 표준 생성 metric: MSR-VTT에 COCO CIDEr/METEOR/BLEU suite와 충분한 test 규모가 필요하다.

7. 다음 세션 실행 순서

  1. Media-policy gate 확인: configs/nextqa_media_policy.yaml과 실제 media inventory/checksum을 검증한다. 개인 acceptance record를 만들지 않는다.
  2. 완료 — Baseline control: video-only가 가장 강했고 text-only보다 +32.58pp였다. Audio를 첫 trainer에 섞지 않는다.
  3. 임시 joint head 확장 금지: nextqa_joint_head_poc.py는 진단 artifact로 보존하되 더 큰 데이터로 scale하지 않는다.
  4. 실제 Stage 3 구현: 기존 Audio Caption LoRA의 Qwen prefix injection을 일반화해 먼저 video FULL+delta와 question/choices를 하나의 typed sequence로 만든다. Qwen backbone은 LoRA만 학습한다. Video gate가 통과한 뒤 audio와 committed captions를 각각 ablation으로 추가한다.
  5. 빠른 overfit gate: source-disjoint 64/16/16에서 train 생성 accuracy/word-F1가 충분히 오르고, delta zero/shuffle 및 caption-memory removal이 실제 답변을 악화하는지 확인한다.
  6. held-out 비교: 동일 prompt/split에서 vanilla raw Omni, trained delta Omni, FULL-only, zero/shuffle delta, no-caption-memory를 비교한다. Loss만으로 통과시키지 않는다.
  7. 그 다음 scale: 최소 500–1,000 train videos/5K–10K QA로 확장한다. Small PoC가 vanilla gap을 줄이지 못하면 데이터만 늘리기 전에 interface와 rollout을 수정한다.
