DeltaThought · Research design

Qwen2.5-Omni가
First + Delta를 이해하게 만드는 계획

Native Qwen2.5-Omni vision/audio encoders로 causal block embedding을 만들고, 첫 full block과 이후의 압축 delta만으로 modality caption과 전체 QA를 수행하도록 동일 Thinker를 학습한다.

작성일 2026-08-27 · 계획 문서 · 성능 결과 문서 아님

1. 결론: 사용자 구상과의 일치 여부

핵심 구상은 일치한다. Audio와 video는 독립적으로 delta를 축적하고, commit 시점에 scoped caption을 생성한 뒤 해당 modality만 새 full anchor로 갱신한다. 마지막에는 caption memory와 아직 commit되지 않은 state를 사용해 전체 질문에 답한다.

다만 실제 학습 가능한 시스템으로 만들려면 아래 네 요소가 사용자 목록에 명시적으로 추가되어야 한다.

State accumulator

pairwise delta를 단순 연결하지 않고 bounded state에 누적한다. 순서와 누적량을 보존해야 한다.

Commit policy

언제 caption을 만들지 modality별 boundary/trigger head가 결정한다. Caption decoder와 별도 검증한다.

Reset semantics

caption 이후 해당 modality의 anchor/state만 갱신하고 다른 modality의 시간 상태는 건드리지 않는다.

Temporal serializer

Qwen2.5-Omni TMRoPE 시간축을 유지하며 full/delta/audio/video block을 Thinker 입력에 interleave한다.

4. Delta를 Thinker에 넣는 방법

권고: continuous delta slots

Delta content는 K × 3584 continuous embeddings로 만들고 Thinker의 inputs_embeds에 직접 삽입한다. Qwen의 native multimodal interface 자체가 continuous encoder embedding을 사용하므로 가장 자연스럽다.

권고정보 손실 최소

대안: discrete VQ delta codes

Delta를 codebook ID로 양자화하여 vocabulary처럼 입력한다. 저장·전송에는 좋지만 초기 연구에서는 quantization confound가 추가된다.

후속 ablation

<FULL_V>, <DELTA_V>, <CAPTION_V>, <RESET_V> 같은 control token은 discrete special token으로 추가한다. 즉 control은 token ID, 실제 delta 내용은 continuous slots로 분리하는 것이 1차 권고안이다.

5. 데이터 전략: 하나가 아니라 부분 supervision의 결합

채택 전 credibility gate

기능이 맞는다는 이유만으로 데이터셋을 채택하지 않는다. 아래 hard gate를 통과하지 못한 후보는 구현 편의와 무관하게 주 학습·평가에서 제외한다.
  1. 학술 검증: 2년 이상 된 데이터셋은 원칙적으로 Semantic Scholar/Crossref 기준 100회 이상 인용. 신생 데이터셋은 top-tier peer review와 다수의 독립 benchmark 채택이 모두 필요하다.
  2. 실사용: 공식 download 통계, benchmark submission, 독립 downstream 논문, Hugging Face/GitHub adoption 중 최소 두 신호를 확인한다. 다운로드 수만으로 품질을 판단하지 않는다.
  3. 공식성: 저자·기관 공식 배포, 고정 version, annotation card, split 정의가 있어야 한다.
  4. 라이선스: annotation과 media 각각의 이용 조건을 검증하고 동의 기록을 남긴다.
  5. 가용성: YouTube 기반이면 실제 media attrition을 측정한다. 가용률이 낮거나 class별 결측이 편향되면 사용하지 않는다.
  6. 누출 방지: 다른 dataset과 원본 source가 겹치면 source-group split을 적용한다.

2026-08-27 보수적 citation snapshot: ActivityNet Captions 1,624, Ego4D 629, AudioCaps 749, Clotho 620, MUSIC-AVQA 274, AVQA 182, AVSD 233. 집계 서비스별 차이가 있어 더 낮게 확인된 값을 우선 사용한다. Perception Test는 NeurIPS 2023 공식 benchmark지만 정량 adoption snapshot을 한 번 더 고정하기 전에는 acquisition을 시작하지 않는다. PerceptionLM/PLM data는 2025년 신생이며 확인 인용이 1회 수준이라 현재 주 데이터셋에서 제외한다.

단일 sample에 모든 label이 있을 필요는 없다. 공통 episode schema에서 없는 label은 명시적으로 unknown으로 mask하고, dataset별로 관측 가능한 loss만 계산한다. 없는 caption이나 event를 “no change”로 변환하면 안 된다.

Caption 학습 source와 QA 학습·평가 source를 분리한다

Caption 전용 source pool

ActivityNet Captions/Ego4D는 video caption, AudioCaps/Clotho는 audio caption에 사용한다. Joint audiovisual caption dataset은 credibility gate를 별도로 통과한 경우에만 추가한다.

Stage 2 only

QA 전용 source pool

NExT-QA, MUSIC-AVQA, AVQA, AVSD, Perception Test 중 credibility/license gate를 통과한 dataset을 Stage 3 QA SFT와 held-out 평가에 사용한다. 이 media에는 caption ground truth를 학습하지 않는다.

Stage 3 only

Global source-overlap audit

Dataset 이름이 달라도 YouTube ID, 원본 URL, media hash가 같으면 동일 source다. Caption pool과 QA pool 사이의 모든 중복 source를 제거하고, 제거 전후 class/domain 분포를 보고한다.

hard invariant
ActivityNet Captions를 caption 학습에 쓰면 ActivityNet-QA는 QA 결과에서 제외한다. AVSD를 QA에 쓰면 AVSD summary/caption은 caption 학습에 쓰지 않는다. “같은 영상의 caption을 학습하고 그 영상의 QA를 맞히는” 평가는 직접 answer leakage가 아니더라도 content memorization confound이므로 금지한다.

최소 credible 조합

  1. Caption SFT: ActivityNet Captions 또는 Ego4D + AudioCaps + Clotho.
  2. QA SFT: NExT-QA + MUSIC-AVQA/AVQA + AVSD train splits.
  3. Untouched QA: Perception Test 및 각 QA dataset의 source-disjoint official test.
  4. Dataset-family exclusivity: 같은 원본 family는 caption 또는 QA 중 한 역할만 맡는다.

SSV2·AudioSet은 engineering baseline에 유지한다. NExT-QA는 QA 전용으로만 사용한다.

  "text": {"transcript": null, "subtitle": null, "ocr": null},

  "metadata": {}

위 코드는 요약 예시다. 전체 필드와 nested field는 machine-readable JSON Schema에서 강제한다. null은 dataset이 해당 annotation 종류를 제공하지 않는다는 뜻이고, 빈 배열은 annotation 종류는 제공하지만 해당 episode에 item이 없다는 뜻이다. 상세 규약은 Canonical data format v2에 있다.

  • 모든 dataset adapter는 이 schema만 출력하고 모델 코드는 dataset 이름을 알지 않는다.
  • 동일 YouTube/source가 여러 dataset에 나타나면 source-group 단위로 split하여 leakage를 막는다.
  • 모든 block은 원본 timestamp를 보존하고 2초 경계를 넘는 label은 overlap 비율과 함께 기록한다.
  • 자동 생성 caption/QA는 human annotation과 별도 필드에 보존하며 최종 test 정답으로 사용하지 않는다.
  • 질문의 정답 문자열이 caption에 직접 포함되는지 기록해 QA leakage 결과를 별도로 보고한다.

7. 학습 curriculum

단계입력/학습 대상Loss다음 단계 진입 조건
P0 Raw Omni baseline 공식 full A/V input, 전부 freeze 없음 또는 dataset 표준 SFT 실제 caption/QA 기준 성능과 비용 측정
S1 Delta representation Native encoders freeze, modality delta/accumulator train step/section reconstruction, identity, temporal contrast, order normal이 zero/last/reverse/shuffle보다 우수
S1 Delta interface Teacher=raw Omni, student=first+delta, Thinker freeze hidden alignment, output KL, temporal/semantic probes first+delta representation이 causal controls를 통과
S2 Caption + commit Commit heads, control embeddings, delta interface, caption LoRA boundary BCE/focal, caption CE, teacher KL, latency regularizer boundary F1 + actual modality-caption 품질
S3 Independent QA Caption LoRA freeze + 별도 QA LoRA; caption과 source-disjoint QA media answer CE, evidence/required-modality auxiliary losses 동일 QA SFT 후 caption-curriculum branch가 no-caption control보다 우수
확정된 학습 제약: Qwen2.5-Omni Thinker는 항상 LoRA로만 학습한다. Native vision/audio encoders와 base Thinker weights는 모든 단계에서 freeze하며 full fine-tuning 경로는 구현하지 않는다. Frozen-interface run은 LoRA 효과를 분리하기 위한 baseline으로만 남긴다.

Stage별 LoRA 구성

S2에서 LoRA_caption을 학습한다. S3에서는 이를 freeze하고 새 LoRA_QA를 추가하여 base Thinker 출력에 두 low-rank update를 합성한다. Caption이 QA에 기여했는지 분리하기 위해 control branch는 LoRA_caption=0인 동일 S1 checkpoint에서 시작해, 같은 초기값·QA data·step 수의 LoRA_QA만 학습한다.

Stage 2 내부의 부분 supervision sampling

Video-caption batch, audio-caption batch, boundary batch, unlabeled teacher-student batch를 ratio로 섞고 sample의 supervision mask가 켜진 loss만 계산한다. QA batch는 이 stage에 절대 들어오지 않는다. S3는 QA dataset만 사용하며 S2의 caption/delta modules를 고정한다.

QA stage의 실제 입력

QA media에는 caption ground truth가 없다. Freeze된 S2 system이 first+delta stream에서 caption을 먼저 생성하고, S3는 그 generated caption memory와 아직 commit되지 않은 active delta state, question을 받아 answer를 학습한다. 따라서 train과 inference 조건이 일치한다.

9. 구현 및 실험 순서

  1. 공식 Omni Thinker의 raw video/audio token shape, token/sec, VRAM, throughput 측정.
  2. Raw Omni baseline을 Perception Test 또는 우선 확보된 joint dataset에서 측정.
  3. 공통 episode schema와 source-group split verifier 구현.
  4. 두 modality의 2초 causal block cache 생성. Encoder revision과 processor config를 manifest에 기록.
  5. Video/audio delta slot 수를 별도로 탐색. 동일 수로 고정하지 않음.
  6. S1 codec/interface 학습 및 same-class temporal controls 통과.
  7. Continuous delta serializer를 Thinker inputs_embeds와 TMRoPE에 연결.
  8. S2 caption/commit LoRA 학습과 actual caption 평가.
  9. Caption source와 전역 중복이 제거된 QA dataset에서 S3 QA LoRA 학습.
  10. Q0/Q1/Q2/Q3 QA branch와 caption masked/shuffled ablation 비교.
  11. 긴 full training, multi-seed actual generation, efficiency 및 failure analysis.
공식 checkpoint와 project-local torchvision 의존성을 고정했고 native encoder smoke가 통과했다. 현재 설정의 독립 2초 block은 video 100 tokens, audio 50 tokens, width 3584이며 batch-one 반복은 bitwise exact였다. 다음 단계는 dataset credibility/license/source-overlap audit이다.

10. 확정된 설계 선택

Delta content 표현

확정: continuous slots로 먼저 증명하고 discrete VQ는 후속 ablation으로 둔다.

Commit 결정 주체

확정: modality별 commit head가 boundary를 결정하고, Thinker는 caption/control token을 생성하는 hybrid 방식.

1차 통합 데이터셋

확정: 검증된 caption dataset과 source-disjoint QA dataset을 역할별로 분리한다. ActivityNet/Ego4D, AudioCaps/Clotho는 caption 후보이고 NExT-QA, MUSIC-AVQA/AVQA, AVSD, Perception Test는 QA 후보다. PLM은 현재 제외한다.

Caption memory의 최종 QA 노출

확정: 생성 caption과 아직 commit되지 않은 active delta state를 모두 QA에 제공한다. Caption-only/state-only/shuffled-caption은 ablation으로 둔다.

11. 현재 범위와 다음 행동

기존 DINOv2/CLAP/separate-Qwen 결과는 Qwen2.5-Omni가 first+delta를 이해한다는 증거가 아니다. 공식 Omni 경로에서는 아직 raw baseline, delta training, caption, QA 결과가 모두 남아 있다.

설계 선택은 확정됐다. 다음으로 dependency 추가와 encoder smoke를 재개하고, 데이터 취득 전에는 각 후보의 credibility·license·source-overlap audit 결과를 먼저 보고한다. Raw Omni baseline을 고정하고 각 단계의 actual-task gate를 통과하지 못하면 다음 단계로 넘어가지 않는다.
